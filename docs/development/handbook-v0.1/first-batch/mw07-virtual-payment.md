## MW07-A 工作范围

1. 查阅微信官方现行文档，至少覆盖：
   - 虚拟支付主指引（企业/个体户）
   - 个人主体入口
   - Android、鸿蒙、Windows、iOS/Apple 支付条件
   - 沙箱、现网、退款和技术服务费
2. 只读核对本项目小程序后台：
   - 名称是否为思维工坊
   - 主体类型：个人、个体工商户、企业或其他
   - 主体认证状态
   - 当前服务类目/经营类目
   - 备案状态
   - 是否出现“虚拟支付”相关菜单或资格入口
   - 可申请、审核中、已开通、不符合资格或其他状态
   - 是否具备沙箱入口
   - 是否能看到 OfferID、商品、通知配置等入口（只核存在性，不创建）
   - Android / 鸿蒙 / Windows / iOS 分别可用、受限或待确认
3. 建立资格矩阵，每项使用 PASS / FAIL / BLOCKED / NOT_RUN。
4. 输出 MW07-B 输入清单：只列变量名、存放方式和准备状态，不取得秘密。
5. 明确判断 B 是否现在可以启动；若不能，列出缺少的用户操作、材料、审核或平台资格。缺口不得阻止 MW08—MW19 普通业务开发。

需要登录、扫码、验证码或敏感信息时暂停，由用户亲自操作。不得要求用户在对话中发送账号密码、验证码、身份证资料或密钥。

## MW07-B 工作范围（本轮不执行）

B 依赖 A 的明确资格结论，以及 MW04 已锁定的 mw-test 云端能力。启动 B 前至少具备：

- 主体与渠道资格已确认，或已记录可继续的有限技术样例范围
- 虚拟支付已开通，或官方允许的沙箱/现网测试入口可用
- OfferID 已存在或已获准创建
- AppKey、通知 Token/AES 等秘密已由用户写入被忽略的本地配置，对话与仓库均不出现真实值
- 明确授权的测试商品标识，且未对外定价
- 通知 URL 与协议类型已规划，但本轮 A 不配置回调密钥

B 只做隔离样例：签名算法对照官方测试向量、查单、通知验签、发货确认。真实扣款必须另有金额、次数和退款安排授权。iOS Apple 支付只能现网验证，不能用沙箱替代。

- 建议用普通微信支付、二维码、外部网页或人工开 VIP 替代在线支付
