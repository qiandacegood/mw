## 1. 目标

在既有 MW02 设计和 MW13—MW16 前端之上，确立后续页面可复用的 TDesign 视觉基线，并在真实小程序答题路由 `apps/miniprogram/pages/quiz/index` 落地一个可操作样板。

交付必须同时包括规范、实际组件接入、答题页代码和验证记录。仅有设计说明、截图或独立 HTML 演示不算交付。此轮不要求所有页面换肤，不重新定义已确定的答题业务。

“定稿”指本轮 UI 实施基线版本化；正式 Logo、运营插画、勋章美术仍可在后续替换。视觉方案由执行者按本文件直接落地，最终交用户审阅，不在动手前重复询问已确定的组件库和实施范围。

## 3. 工作范围和交付

### A. 更新现有设计基线

更新 `docs/design/visual-spec.md`，保留历史来源并标记本轮版本；同步设计入口，必要时只修订答题相关交互和状态说明。不要另造一套互相冲突的规范。

基线要求：

- 视觉方向：清晰、克制、便于长时间阅读；浅背景、白卡片、细边框，弱阴影或无阴影。
- 延续现有主色 `#2B6CB0`，VIP/勋章金色仅保留为后续主题变量，不在答题页增加营销装饰。采用 TDesign 不等于必须改成其默认蓝色。
- 定义品牌色、背景、文字、边框、选中、成功、警告、错误、禁用等语义变量；同时给出字体、行高、间距、圆角和触控尺寸。
- 参考当前基线：设计宽 375、左右边距 16px、正文 16px、大字号正文 20px/行高 1.6；点击区域至少 44×44px。可按实际组件微调，但必须记录原因和最终值。
- 采用同一套 TDesign 线性图标；注明依赖版本和来源。状态同时有文字或图标，不能只靠颜色区分。
- 建立“业务元素 → TDesign 组件或自有组件 → 状态 → 实际文件”映射表。执行时查阅官方文档核实组件名称、路径、属性和事件格式，不能凭记忆编造 API。
- 主题变量可全局声明，但本轮组件覆盖样式限定在样板或专用类下，避免通用 `button` / `.card` 等选择器意外改变其他页面。

### B. TDesign 接入与构建闭合

使用腾讯官方 `tdesign-miniprogram`，参考：

- https://github.com/Tencent/tdesign-miniprogram
- https://tdesign.tencent.com/miniprogram/overview

核对当前稳定版本、基础库要求、许可证和实际安装产物，锁定具体版本并更新项目现有锁文件，不写浮动 `latest`。按样板所需注册组件，不引入第二套 UI 库或复制修改第三方源文件。

**现有构建有明确适配点：** `build-miniprogram.mjs` 会删除 `miniprogram_npm`，目前仅重建 `@mw/shared`；导入检查器目前对裸包名只处理 `@mw/shared`。必须按实际安装结果解决 TDesign 组件 JS/JSON/WXML/WXSS/WXS 及资源的构建、依赖路径和检查，必要时扩展本地组件 TypeScript 入口收集。不得靠跳过第三方目录的全部校验来掩盖缺失依赖。

可以采用官方支持的 npm 构建方式或最小工程适配，需写清可复现顺序。若还需要微信开发者工具“构建 npm”，必须明确操作顺序及重复构建后的恢复方式，不能只在本机手工复制一次后宣称完成。用当前构建、按说明完成 npm 构建、再次重复的方式验证组件仍可加载，同时保留现有 `@mw/shared` 运行能力。

记录包体变化和开发者工具编译结果；如超平台实际限制，在本任务内缩减依赖，不扩大成全站分包重构。

### C. 实际答题页样板

改造既有 `pages/quiz/index`，维持原路由及真实接口接线，不新建第二套答题业务实现。

页面包含：

1. 试卷标题、当前题号/总题数、已答数量、清晰的保存状态。
2. 题型标签、题干、选项；单选/多选/判断以现有数据模型为准，不显示多选正确项数量。
3. 选项默认、选中、不可操作等状态；答题中不显示正确答案、对错颜色或解析。正确/错误视觉仅在规范中定义供后续结果页使用，不额外实现结果页换肤。
4. 答题卡：当前题、已答、未答可区分，可跳题，可容纳最多 100 题；“已答”不得被表现为“答对”。
5. 底部操作区：上一题、下一题、答题卡、交卷的主次清楚；窄屏可调整布局，考虑安全区，不遮住最后一个选项或长题干。
6. 加载、加载失败与重试、未保存/保存中/已保存/保存失败/版本冲突/离线、提交中、已提交转结果等实际状态；原有危险确认可以保留原生弹窗，或在保持语义前提下映射到 TDesign。
7. 如现有接口提供题图/选项图字段，保留或补齐本页显示、加载失败重试和放大预览。先核实字段和既有私有媒体读取方式；无服务支持则记录缺口，禁止假图冒充真实接线或借此修改服务契约。

仅提取样板实际复用或后续明确通用的少量 UI 单元，如保存状态、选项、答题卡；不要提前造完整组件平台。TDesign 组件事件需要显式适配原业务参数，特别检查 optionId、多选数组和跳题序号。

现有测试/leftover 入口保留原有可达性和主动记入语义，可收纳进明确标识的折叠测试区；打开页面或展开面板不得自动写清单。不要全站删除调试入口。

### D. 保持的业务边界

- 选择后走现有保存流程；只有服务器确认才显示已保存，未同步内容不能伪装为保存成功。
- 保存中/保存失败是否可交卷沿用有效实现与契约，不能为了组件 loading 样式擅自禁用；版本冲突需按既有方式明确解决。
- 未答确认、最终答案提交、跨设备 revision 冲突、恢复草稿和已提交只读语义保持。
- 交卷处理中防重复操作、超时按原 attempt 查状态，不新建一轮；不增加客户端判分、不提前拉取答案。
- 登录、VIP 判权、紧急撤回、权限错误仍遵守既有服务结果；不提前实现 MW20 的真实权益。
- 如发现既有代码与产品规则不一致，记录证据并区分既有缺陷与本轮回归；仅修复本轮事件适配或呈现引入的问题，跨业务缺陷另列待办，不静默扩大范围或掩盖问题。
