版本：1.1  
编制日期：2026年10月3日  
产品形态：微信小程序与网页管理后台  
云平台：腾讯云 CloudBase  
开发根目录：F:/MW/main  
适用对象：产品负责人、设计人员、开发人员和测试人员

本说明书定义思维工坊第一版的功能、业务规则和验收要求。产品以“选择试卷、完成练习、阅读解析、积累成绩”的方式，帮助普通成年用户练习不同思维方法。首版包含在线购买 VIP 和多维排行榜，可据此开展页面设计、数据设计与开发拆分。V1.1 纳入类目可维护且最多三级、所有试卷统一计入排行榜、腾讯云 CloudBase 三项最新决定；V1.0 保留为历史版本。

用户已确认第 2 节的需求，并授权补充排行榜及必要产品设计。除第 2 节已确认规则外，其余新增业务细节与技术配套规则属于首版设计，是本说明书提出的实施基线，不冒充用户逐条裁决；标为“上线前待定”的价格、主体及运营材料不使用假定值上线。本文不代表程序已实现、支付资质已开通或上线验收已完成。

## 1 产品目标与范围

### 1.1 产品目标

让用户能方便地找到想练习的思维类目，通过答题与解析学习思路，并借助成绩、成长等级、勋章和排行榜持续参与。分数表示在本产品题库中的答题表现，不作为智力、心理或专业能力的测评结论，也不承诺练习必然产生某种效果。

客观题适合练习识别思路、比较方案和判断理由；发散思维、创造性思维等类目也采用此形式，但不能把客观题成绩等同于完整的创造能力。

## 4 类目与内容结构

### 4.1 初始类目

| 类目 | 出题方向示例 |
| --- | --- |
| 逻辑思维 | 条件推理、关系判断、因果辨析 |
| 逆向思维 | 从结果追溯条件、反证、倒推 |
| 发散思维 | 比较多种用途、路径与可能解释 |
| 聚合思维 | 在明确条件下筛选最合适的方案 |
| 形象思维 | 图形规律、空间关系、视觉转换 |
| 抽象思维 | 提取共同特征、概念分类、规律归纳 |
| 创造性思维 | 识别新颖且符合约束的组合方案 |
| 批判性思维 | 证据判断、论证漏洞、信息可信度 |
| 博弈思维 | 策略互动、收益比较、合作与竞争 |
| 开放性思维 | 多角度理解、修正假设、容纳不同解释 |

这十个一级类目是初始配置，可以增减和修改，不是写死的类目枚举。以上是选题方向，不构成科学测评量表。具有明显主观性的题目必须交代判断依据，避免把个人偏好设为唯一正确答案。

### 4.2 归属与身份

最多三级，根类目为第一级。可以只使用一级或两级，不强制补齐三级。每张试卷只直接归属一个有效类目，一、二、三级均可挂卷；父类目页面包含本级及所有后代类目的试卷，按试卷标识去重。

题目主类目用于题库组织，可以被不同类目的试卷引用；计分归属以试卷为准，同一张卷不得重复引用同一道题。管理员负责保证题目与整卷练习目标适配。

支持新增、改名、排序、启停及调整父级。停用节点及其后代不供新发布和新答题选择，分类导航与分类榜隐藏，合法历史成绩仍计入总榜及周月榜；重新启用恢复原有分类分。停用不自动撤回已经开始的试卷。服务端拒绝第四级、自身为父、移入后代、缺失父级和同一父级下重名。移动整个子树后仍必须最多三级。

删除采用逻辑删除，保留稳定标识和历史名称；无子类目且无当前题目或试卷引用时可删除。有子类目先移动或逐级删除；有题目、试卷时先选择目标有效类目迁移，系统不能擅自决定归属。历史答题和发布快照引用不删除。可在同一后台维护任务中预览并确认迁移后删除。

父级调整和试卷类目迁移会按新归属重新汇总分类成绩，累计总分、周月进步分、等级及勋章不变，也不产生新增分。历史记录仍显示当时类目路径，当前分类统计使用现行路径；类目改名不创建新类目身份。批量迁移及分类汇总期间短暂暂停内容结构写入和交卷，允许保存草稿、查订单与支付，完成一致性检查后恢复。

类目、题目、试卷、用户和订单各有系统生成的稳定标识；名称不作为标识。题目修改产生新版本，试卷发布后保存当时题目的内容、答案、解析、分值和图片引用快照。

### 4.3 试卷属性

必需属性包括稳定标识、标题、类目、简介、练习目标、难度、免费或 VIP、排序、题目列表、题目顺序、每题分值、满分、发布状态和版本。难度采用入门、进阶、挑战三个标签，由管理员设置，不据此计算额外奖励。

首版设计每卷 1—100 题，每题 1—100 整数分；满分为各题分值之和。不强制所有卷同分，但建议首批卷以 20 题、每题 5 分、满分 100 分为主要规格。不同规格必须明示，排行榜中的分类分表示累计练习表现，不直接代表不同类目间的能力强弱。

建议时长仅供参考，首版不设置强制倒计时或超时交卷。题序和选项顺序固定，便于学习及错误排查。

## 5 题目与内容要求

### 5.1 题目结构

每题包含题型、题干、选项、正确答案、解析、默认分值、类目和难度。解析必须说明判断理由，多选题应解释容易漏选或误选的选项。试卷可在草稿阶段覆盖题目的默认分值，评分以发布快照为准。

| 题型 | 内容校验 | 判分 |
| --- | --- | --- |
| 单选 | 2—8 个不重复选项，且只有一个正确答案 | 选择正确选项得全分 |
| 多选 | 3—8 个不重复选项，正确项至少 2 个且少于总选项数 | 所选集合与正确集合完全相同才得全分 |
| 判断 | 固定“正确”“错误”两个选项，正确答案只有一个 | 判断正确得全分 |

多选题显示“多选题”，不提前显示正确选项数量。未作答按 0 分，不视作系统失败。选择顺序不影响多选判分。

### 5.2 图片与展示

为支持形象思维，首版题干、选项和解析可以附静态图片；文字仍是基本内容。后台上传 JPG、PNG、WebP，单张不超过 2 MB，并填写简短说明。图片由受控存储提供，不接受任意外链、可执行 HTML、脚本、SVG 或动态嵌入。

图片支持点击放大；图片加载失败需明确提示并允许重载，不能把缺图题当作完整题目显示。导入表格首版只支持已有素材标识，新增图片通过后台上传，不通过任意本地路径或远程 URL 抓取。

### 5.3 发布检查

发布必须通过题目结构、答案合法性、解析非空、图片可访问、类目有效性、重复题、满分计算和整卷预览检查。自动检查负责结构与完整性，内容正确性与版权来源由管理员人工审核。

## 6 注册与个人资料

首版设计采用微信登录及服务端身份校验。首次注册前展示用户协议和隐私说明，由用户主动确认；不预先勾选。拒绝注册时仍可浏览公开内容，答题入口提示注册。

生成内部会员标识，关联本小程序的微信身份。同一身份重复登录不新建会员，跨设备登录后读取同一账号的草稿、成绩和权益。账号合并和跨小程序身份迁移不在首版范围内。

不强制索取手机号或微信头像昵称。默认生成展示昵称和默认头像；用户可以修改昵称、选择内置头像。昵称需要长度校验和适用的内容安全处理，具体平台接口在技术设计阶段核实。

个人页包含成长等级、总分、当前类目得分、勋章、VIP 状态及到期时间、答题记录、订单、排行参与开关、协议、客服和账号注销入口。注销经身份确认后退出公开榜单并处理个人数据；支付记录按适用要求保留最小必要信息，保留范围与期限在隐私方案中落实，不承诺立即删除全部交易记录。

## 8 答题与成绩流程

### 8.1 开始与保存

1. 服务端校验会员状态、试卷可用性及 VIP 权限，创建绑定试卷版本的答题记录。
2. 每个账号同时只保留一份进行中的试卷。开始另一卷前，提示继续原卷或放弃原草稿；放弃不计分，保留必要记录。
3. 用户选择答案后自动保存，页面区分“保存中、已保存、保存失败”。只有服务端确认的内容才显示已保存。
4. 首版不支持离线完成和离线交卷。断网时可保留当前页面尚未同步的选择并提示；恢复连接后核对版本再保存，不声称未同步答案已保存成功。
5. 返回页面、重新登录或换设备后恢复已保存进度。多设备通过草稿版本冲突提示避免旧页面静默覆盖新答案。

### 8.2 交卷

交卷前显示已答及未答题数；存在未答题时要求确认，说明未答题计 0 分。交卷请求携带最终答案，服务端一次性校验、评分和结算，避免依赖仍在发送中的自动保存。

交卷成功后答案锁定，重复提交同一答题记录返回相同结果，不重复增加成绩。网络超时后按原答题记录查询状态，不能自动创建新一轮答题。已完成记录可以随时查看，重新练习必须创建新记录。

### 8.3 权限变化与内容下架

首版设计：VIP 卷在开始、恢复及交卷时均校验有效期。答题期间到期时保留草稿，提示续期后继续提交；不删除已答内容。后台停用账号时禁止新增答题与交卷，订单查询和客服应保持必要可用。

普通下架只阻止新开始；已经开始的快照允许完成。因答案错误或违规内容紧急撤回时，阻止未提交记录交卷并说明原因。已提交的历史成绩不自动删除，后续按第 13 节纠错；违规内容的解析可按具体处置限制展示。

## 9 计分与成长

### 9.1 计分公式

本次卷分 = 本次各题实际得分之和。  
某卷计入分 = 该会员对同一稳定试卷标识的全部有效已提交记录中的最高分；未交卷为 0。  
总分 = 各张试卷计入分之和。  
某类目分 = 直接归属该类目及其所有后代类目的各张试卷计入分之和，每张卷只计一次。父类目分已含后代分，不可再次叠加父子分求总分。  
本次新增分 = max(0，本次卷分 − 交卷前该卷最高分)。

例如同一卷依次获得 60、80、70 分，三次分别新增 60、20、0 分，该卷最终计入 80 分。另一卷得 50 分后，总分为 130 分。正确率按正确题数除以总题数计算，仅用于该次结果展示，不代替加权分值。

免费卷与 VIP 卷使用相同判分规则；购买 VIP 本身不加分，不设 VIP 分数倍数。正常练习不会降低总分。内容纠错、作废作弊记录等例外必须有独立记录，并同步修正汇总和排行。

### 9.2 成长等级与勋章

成长等级由总分落入的区间决定，VIP 不参与等级计算。每个等级关联一枚勋章，首次达到门槛自动授予，跨多级时补齐经过等级的勋章。正常情况下勋章永久保留；因纠错造成降级也保留既得勋章。仅确认作弊等特殊处置可由超级管理员说明原因后撤销相关勋章。

以下是可开发使用的初始建议配置，不是已确认的最终运营门槛；上线前结合实际发布卷量确认，避免最高等级根本无法达到。

| 等级 | 名称 | 最低总分 | 勋章名称 |
| --- | --- | --- | --- |
| L1 | 思维新芽 | 0 | 新芽 |
| L2 | 思维学徒 | 100 | 启程 |
| L3 | 思维探索者 | 300 | 探索 |
| L4 | 思维进阶者 | 800 | 进阶 |
| L5 | 思维实践者 | 1500 | 实践 |
| L6 | 思维领航者 | 3000 | 领航 |

注册后获得 L1 及新芽勋章。后台校验等级门槛从 0 起严格递增，名称与勋章不可缺失。修改门槛必须预览影响人数并确认后发布配置版本，按现有总分重算等级、补发新达到的勋章，不因门槛修改删除既得勋章。

## 10 多维排行榜

### 10.1 四个榜单

| 榜单 | 指标与周期 | 用户价值 |
| --- | --- | --- |
| 总分榜 | 全部有效试卷历史最高分之和，累计 | 展示长期积累 |
| 分类榜 | 选定任一级有效类目及其后代范围内的累计分 | 查看某类练习表现 |
| 本周进步榜 | 本自然周内产生的有效新增分之和 | 为近期参与者提供机会 |
| 本月进步榜 | 本自然月内产生的有效新增分之和 | 展示阶段性积累 |

周和月指标来自交卷结算事件，不是周期内卷分相加，也不是周期内完成次数。首次完成新卷产生的新增分也计入。已有卷提高 20 分，本周及本月各增加 20 分；反复达到原最高分不增加。产品不把该指标解释为经科学测量的能力提升。

周从北京时间周一 00:00 开始，到下一周周一 00:00 前结束；月从当月 1 日 00:00 开始，到下月 1 日 00:00 前结束。跨边界以服务端首次接受有效交卷的时间归属周期，重复请求不改变归属。周期切换只重置展示窗口，不清零累计总分及等级。

四个榜单均统一计入免费卷和 VIP 卷，不按付费状态、套餐或当前会员身份分榜。试卷列表仍可按免费或 VIP 筛选，便于选卷，这不影响排行计分。

### 10.2 排名与展示

首版设计显示前 100 名，并为登录且参与排行的用户展示本人名次、指标值及与上一名的分差。并列时采用竞赛排名，例如 1、1、3；同分用户内部按首次达到当前指标的时间、再按内部稳定标识排序，仅保证展示稳定，不打破并列名次。前 100 名边界包含第 100 名的全部并列用户，分页加载。

分数为 0 的用户不进入对应榜单。分类榜无有效类目分时显示尚未上榜。时间不是评分因素，不以答题速度鼓励猜答。

### 10.3 隐私与公平

新会员默认不参与公开排行，由本人主动开启。未开启时仍正常计分和成长，榜单本人区域提示“未参与公开排行”。开启后按已有有效成绩参与当前榜，关闭后在下次刷新移除公开展示，不清空个人成绩。公开榜只显示经审核的展示昵称、内置头像、成长等级、排名和本榜分值，不显示手机、微信身份或订单信息。

重复练习与查看历史解析是学习机制，因此榜单不承诺测验防作弊或严格能力比较。服务端仍必须防止伪造答案结算、重复提交加分、越权改分与异常请求。人工禁榜保留原因和审计，不任意改写用户原始答题记录。

### 10.4 刷新与纠错

目标为正常交卷后 60 秒内刷新榜单，显示数据更新时间；个人结果页立即返回此次结算结果。周期榜首版只展示当前周和当前月，保留必要历史结算数据，不建设历史赛季页面。

成绩纠错追溯重算该用户该卷的有效成绩序列和分差事件，并归回原交卷周期；不把旧成绩修复当成本周新增练习。禁榜用户从榜单排除，不改变其他用户自己的分值。

## 11 VIP 套餐与有效期

### 11.1 权益和套餐

首版采用全站 VIP：有效期内可以练习全部已上架 VIP 卷，免费卷仍可正常练习。不按类目单卖、不设置多档 VIP 权益。

初始套餐建议为 30 天、90 天、365 天，售卖页直接写明天数，避免“一个月”与自然月天数混淆。实际售价及最终上架套餐由产品负责人上线前决定。开发期间使用明确标注的测试商品和测试价格，不把示例价格发布为正式售价。

套餐包含内部标识、支付平台商品标识、名称、时长、价格、渠道适用范围、排序和上架状态。金额使用人民币分存储。商品或价格调整创建新配置版本，旧订单继续按下单时冻结的权益和价格处理。

### 11.2 开通与续期

未开通或已到期用户：新到期时间 = 本次权益实际发放时间 + 购买天数。  
仍有效用户：新到期时间 = max(当前到期时间，本次发放时间) + 购买天数。

一天按 24 小时计算；服务端以 UTC 保存时间，用户界面按北京时间显示到秒。到期时间恰好到达时即失效。举例：2026年10月3日 10:00 首次发放 30 天，到期为 2026年11月2日 10:00；到期前再买 30 天则顺延至 2026年12月2日 10:00。

权益发放延迟时从实际成功开通时起算未生效时长，避免让用户为系统故障期间损失服务时间。一次订单只能产生一次有效发放；多个不同已付款订单按同一账号顺序处理，不能互相覆盖到期时间。

### 11.3 人工处理

超级管理员可人工赠送或延长 VIP，必须记录原因、操作者、时长及前后有效期。人工权益有独立来源，不伪造在线付款订单。

首版不设置任意清空付费会员有效期的按钮。误赠只能撤销相应人工权益的未使用部分；付费订单通过退款流程处理。账号违规停用与 VIP 账本分别记录，不把停用伪装成退款或改写支付状态。

## 12 在线支付与退款

### 12.1 支付渠道基线

本产品售卖数字内容访问权限，设计采用微信小程序虚拟支付的道具直购模式，以 VIP 天数套餐作为商品，不采用充值代币或自动续费。微信官方当前文档要求相关虚拟商品使用虚拟支付，并说明该能力覆盖 Android、iOS、鸿蒙及 Windows；iOS 由 Apple 支付承接。[微信虚拟支付接入指引](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)

截至2026年10月3日核对，企业及个体户指引中的 iOS 条件包括 iOS 15 及以上、微信 8.0.68 及以上、中国大陆 App Store 账号、订单金额至少 1 元；Apple 支付只能在现网验证，不能用沙箱验证替代。[同一官方指引](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)

以上是当前官方能力说明，不表示本项目账号已具备资格。实际主体类型尚未提供，开发前须核对相应主体入口及经营类目。iOS 与 Android 都列为首版目标，不能自行删掉任一端的在线支付；如资质或平台限制导致无法交付，应形成明确问题供负责人决定。客户端版本不足时提示升级，不诱导外部绕行购买。

### 12.2 购买流程

1. 用户登录后进入 VIP 中心，查看权益、套餐天数、应付价格、现有到期时间、服务与退款说明。
2. 用户确认套餐；服务端依据已发布商品创建订单并冻结金额、时长、账号和渠道信息，不能信任客户端传入的价格。
3. 服务端生成必要支付参数，客户端拉起平台收银台。
4. 返回小程序后显示“确认支付结果”；服务端通过经过校验的平台通知或主动查单确认真实支付状态。
5. 确認已付款后，幂等发放 VIP，持久化权益成功后确认发货。页面展示开通结果和新到期时间。
6. 付款已成功但开通尚未完成时显示“已支付，权益开通中”，提供刷新状态与客服入口；系统持续核对同一订单，不要求用户再买一次。

平台回调可能丢失，不能仅凭客户端 success 开通权益；支付通知与查单应互相补足。这里的业务要求与微信普通支付开发指引关于服务端查询确认的原则一致，但具体接入必须使用所选虚拟支付接口，不能直接拿普通支付接口替代。[微信支付开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791911)

### 12.3 订单与幂等

付款、权益发放、退款采用独立状态，不能用一个“成功”字段代替所有阶段。

| 维度 | 首版状态 |
| --- | --- |
| 付款 | 待支付、确认中、已支付、已关闭 |
| 权益发放 | 未发放、处理中、已发放、处理异常、已撤回未用部分 |
| 退款 | 无退款、申请处理中、渠道处理中、成功、失败 |

本地订单号和平台交易号均做唯一性约束。回调必须校验来源、环境、商品、账号、金额与订单匹配；异常进入待核对，不开通、不丢弃证据。测试通知不得影响生产权益。

连续点击购买应复用同一购买请求；只有明确发起新的购买才创建新订单。用户取消收银台不等于订单已关闭；不确定结果先查单。待支付订单首版目标有效期为 15 分钟，最终以渠道支持及查单关单结果为准，不能只凭本地倒计时宣布失败。支付与关单竞争时按渠道真实结果处理，不能漏发已经付款的权益。

订单列表按付款时间及订单创建时间展示状态，用户只能查本人订单。后台支持按订单号、会员、时间、付款状态与发放状态查询，处理“已支付未开通”和账单差异。正式环境每日进行支付及退款对账，异常有可见处理记录。

### 12.4 退款

用户从订单详情查看适合本订单渠道的售后入口。支持商户退款的渠道，由运营人员审核申请，超级管理员确认后向平台发起；平台受理不等于退款成功，必须核对最终结果。

iOS Apple 支付不支持开发者主动退款，用户在 App Store 申请，最终由 Apple 决定；后台需接收并处理退款问询和结果通知，不显示不可执行的“后台退款”按钮。[微信虚拟支付退款说明](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)

首版商户操作提供整笔退款；若渠道发生非整笔退款或其他例外，进入人工核对，不按猜测金额自动削减天数。具体退费资格和面向用户的条款由负责人上线前确认，并遵循渠道适用要求。

确认整笔退款成功后，只撤销该订单尚未使用的权益，保留其他付费或赠送来源的剩余时长。实现应逐来源记录已消耗与未消耗时长：在退款时刻先结算已消耗部分，再删除目标来源剩余时长，其他来源剩余时长按原顺序接续；不能简单把整个 VIP 清零。

例如 A 订单还剩 10 天，后续 B 订单还有 30 天，A 整笔退款成功后仍保留 B 的 30 天。A 已经用完时，退 A 不扣除 B 的时长。重复退款通知只处理一次。退款与发放并发时按同一订单状态串行核对，已确认退款的订单不再新发权益。

退款不删除合法完成的历史成绩、成长等级或历史解析。恶意交易的治理另行保留证据，不把普通退款自动认定为作弊。

## 13 后台内容维护

### 13.1 题库与试卷

题库支持新增、编辑草稿、复制草稿、停用和按类目题型筛选。被已发布试卷引用的题目版本不得直接覆盖或删除。试卷支持草稿编辑、预览、发布、普通下架和紧急撤回。

已发布试卷的免费属性、题目集合、顺序、正确答案、分值和满分冻结；不能为了调价或改分直接改变已有成绩含义。试卷类目允许通过第 4 节的受控迁移调整，不能在普通编辑表单中直接改写分类汇总。标题、简介、推荐排序可保留修改记录后调整，不改变计分身份。

首版不开放已经发布试卷的免费与 VIP 属性互转。需要调整内容或收费方式时，新建实质不同的试卷；不得仅改名字、复制同卷反复发布以扩大可得分。发布时提示与已有卷的题目重合，内容管理员确认实际新增练习价值。

### 13.2 错题纠正

错别字、表述和解析调整可发布同卷修订版；同一稳定试卷标识继续只累计一个最高分。已经开始的记录仍绑定原快照，新开始使用修订版。

正确答案确实错误时，先紧急撤回，再形成修订及影响预览。超级管理员确认后，按保存的用户答案对受影响记录重新评分，重算该卷最高分、总分、分类分及周期分差。修正保留旧记录、前后结果、原因与操作者；相同纠错任务不得重复入账。

首版不支持任意变更已发布试卷题数或分值后自动换算旧成绩。此类变更作为新卷处理。用户历史结果应标识“本记录已因题目纠错修正”，不能静默篡改。

## 14 批量导入

### 14.1 导入形式

首版设计使用 UTF-8 CSV 模板，包含两个入口：题库导入、试卷导入。后台提供模板和字段说明。开发阶段提供虚构示例，不导入真实会员资料。

题库模板字段：导入来源键、类目标识、题型、题干、选项 A—H、正确答案、解析、默认分值、难度、可选题干图片及选项图片素材标识。多选答案采用 A|C 形式；判断答案采用 TRUE 或 FALSE，由页面显示为中文。

试卷模板字段：试卷来源键、标题、类目标识、简介、目标、难度、权限、建议时长、题目来源键、题序、该题分值。同一卷一题一行，卷级字段必须一致，题序必须连续。试卷只能引用已存在且可用的题目来源键，先导题库再导试卷。

### 14.2 校验与提交

上传后先校验并预览，不直接发布。首版单文件不超过 5 MB、最多 1000 个数据行。校验必填、编码、列名、枚举、选项及答案、类目、素材存在、正整数分值、重名来源键、重复题序和每卷题数。

任何阻断错误都使本批不写入，输出行号、字段、原因及修正示例；非阻断疑似重复内容显示提示。确认后原子写入草稿，并记录导入批次、文件摘要、操作者、数量和结果。

来源键是外部导入的稳定引用，不替代内部标识。相同文件摘要再次导入返回原批结果；新文件中已存在的来源键视为冲突，不覆盖原题。首版批量更新既有题目不做，需通过后台修改草稿或明确新版本。

导入内容按普通文本处理，不执行公式、脚本或链接。导出的错误清单应处理电子表格公式注入风险。上传文件只暂存于受控位置，不进入源码仓库。

## 15 后台会员与运营

会员列表支持按内部标识、昵称、注册时间、有效 VIP、成长等级和账号状态筛选；详情展示成绩汇总、权益来源及有关订单，不展示无业务必要的微信身份信息。

套餐发布必须校验支付平台商品已配置、天数和金额一致、目标端可售。下架套餐不影响已支付订单履约。会员人工调整、退款、封禁、禁榜、等级配置发布及成绩纠错均保留操作原因。

基础统计包括注册会员数、当日及累计完成记录数、独立答题人数、每卷完成次数和平均得分、有效 VIP 数、付款订单数、已确认收款金额、退款金额及异常开通订单数。平均分以全部有效已交卷记录计算，界面注明重复练习计入次数；不把支付流水当成净利润。

内容反馈入口归属订单客服之外的独立问题类型，至少能反馈题目或解析错误。反馈关联试卷和题目版本，不能让会员直接修改答案库。

以下是概念模型，正式字段名、数据库类型和索引在技术设计中确定。

| 对象 | 关键内容与约束 |
| --- | --- |
| 会员 | 内部标识、微信身份关联、展示资料、状态、协议版本、排行选择 |
| 类目 | 稳定标识、父标识、级别、祖先路径、名称、顺序、启停与逻辑删除状态、结构版本 |
| 素材 | 标识、受控位置、类型、大小、摘要、引用关系 |
| 题目及版本 | 主类目、题型、题干、选项、答案、解析、图片、版本 |
| 试卷及版本 | 类目、冻结权限、发布状态、题目快照、每题分值、满分 |
| 答题记录 | 会员、试卷版本、答案、保存版本、状态、开始与交卷时间、评分 |
| 单卷最高分 | 会员与试卷唯一组合、最高有效分及来源记录 |
| 分数事件 | 来源交卷或纠错、前后最高分、增量、原始周期归属 |
| 成长配置与勋章 | 门槛版本、授予来源与时间、特殊撤销原因 |
| VIP 套餐 | 商品映射、版本、价格、天数、渠道及上架状态 |
| 订单与退款 | 本地及平台编号、账号、商品快照、金额、渠道、独立状态 |
| 权益流水 | 来源订单或赠送、时长、发放、消耗、撤销、前后有效期 |
| 榜单视图 | 分数汇总、周期、类目范围、参与状态、结构版本、刷新时间，可重建 |
| 后台操作及导入批次 | 操作者、对象、时间、原因、结果、文件摘要 |

成绩原始证据与权益流水必须可追溯。榜单缓存损坏时能从有效成绩与事件重建，不能让缓存成为唯一成绩来源。服务端统一处理时间、身份、评分和权限，客户端不能直接写这些结果。

## 17 安全与质量要求

首版必须区分开发、测试与生产环境；测试会员、测试订单和模拟回调不能进入正式排行或真实权益。支付密钥、微信密钥、个人数据和生产日志不入代码仓库。

未交卷接口不返回正确答案和解析，答案不能藏在前端包或被权限不足的接口获取。成绩、草稿、订单与 VIP 详情均验证资源归属。重复交卷、并发最高分更新、重复支付回调和并发续期采用服务端一致性控制。

后台危险操作明确展示影响再确认；日常答题保存不反复确认。部署前有数据库变更备份和恢复验证，不能以备份文件存在代替恢复可用性。

首版性能验收建议：使用约 1 万会员、1000 张试卷、10 万条答题记录的虚构数据，在约定测试环境以 50 并发请求验证主要读接口 P95 不超过 1 秒、交卷服务端处理 P95 不超过 2 秒，支付外部等待单独记录。此为待技术方案评估的验收目标，不是已测结果或容量承诺。

Android 与 iOS 真机覆盖主要路径，窄屏、大字号、长题干和图片放大不得遮挡提交按钮。平台能力不支持时准确提示，不能仅以开发者工具模拟通过判定支付上线通过。

## 19 开发顺序与交付物

1. 产品与页面设计：依据本说明书确定页面原型、视觉风格、首批题量和上线参数；产出设计稿。
2. 技术设计：确定应用主体、虚拟支付资质与商品接入路线、CloudBase 环境和部署配置、数据结构和接口；早期验证支付可行性，避免到上线前才发现无法售卖。
3. 内容与答题闭环：完成题库、试卷、导入、注册、保存、评分、成绩与解析，使用测试权益验证权限。
4. 成长与排行榜：完成等级勋章、四类榜单、三级类目汇总、参与开关及纠错机制。
5. 在线交易：完成套餐、实际支付接入、发放、续期、订单、退款与对账，包含 Android 和 iOS 差异。
6. 联合验收与发布准备：导入经审核的首批内容、确认运营参数、完成真机及付款验收、隐私材料和发布检查。

前三至四阶段可以内部演示，但第一版正式交付不能以人工开通代替在线支付，也不能把排行榜后置。阶段时间和成本由技术方案及实际人员安排估算，本文不虚构开发工期。
