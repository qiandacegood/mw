# 思维工坊一致性与后台任务 V1.0

日期：2026年10月3日  
关联：[数据模型](data-model-v1.0.md)、[接口契约](../api/api-contract-v1.0.md)。

本文件定义最容易导致重复加分、半成品发布或权益错乱的写入顺序。它是实现约束，不是已执行结果。

## 1 原子交卷

收到 attempt.submit 后：

1. 从可信身份确定会员，加载不可变试卷和答案块，验证答案字段、选项集合、题数、块摘要；计算候选卷分。拒绝多余题号、重复选项及非本卷答案。
2. 开启事务，重新读取 maintenance、会员状态、VIP 摘要、试卷状态和版本、attempt、active_attempts、paper_bests、member_stats。维护状态检查必须在事务内，不依赖事务外缓存。
3. 已 submitted 时先核对 submitHash；相同请求返回旧结果，不同最终答案返回 ALREADY_SUBMITTED。不能由于当前 VIP 已到期而拒绝查询过去成功的同一提交结果。
4. 对进行中的记录校验归属、草稿 revision、权限、当前有效类目路径及未撤回状态。submittedAt 使用最终成功提交事务所采用的服务端时间；失败事务不算有效交卷，重复请求保留首次已落库的时间。
5. newBest=max(oldBest,score)，delta=newBest-oldBest。写入最终答案、分数与状态；更新单卷最高分，清空 active_attempts；member_stats.totalScore 只增加 delta，scoreSeq 加一。
6. 更新 total、week、month 以及含自身的最多三级 category 指标。每个指标都使用事务内读取的当前值加 delta，记录第一次达到新值的时间；delta=0 不刷新达到时间。
7. 同事务创建分数事件、必要勋章任务和榜单刷新任务，返回最终结果。等级用当前配置即时计算，勋章以唯一授予键异步补齐。

事务只按已知 ID 访问，不在其中查询整张题表、扫描历史或调用外部支付。预算约 15—20 次读取、12—16 次写入，实际实现需统计最大 100 题及三级类目情况下的操作数，保持在设计上限 60 内。

事务冲突可有界重试，最多 3 次、总业务预算 10 秒；每次都重新读维护与账号状态。结果未知时查询原 attempt，不生成新尝试。正确答案块必须不可变，否则事务外预评分会失去依据。

## 2 开始和保存

attempt.start 在事务里读取 active_attempts、会员、试卷、维护状态和权益。活动记录存在时返回 ACTIVE_ATTEMPT_EXISTS，不自动丢弃。放弃和开始可以由明确确认后的 startReplacing 操作在一个事务内完成，记录被放弃的 ID。

attempt.save 使用 expectedRevision 和 requestId：先判断幂等，再比较草稿版本。相同请求重放返回原 revision，不同设备的旧版本返回 DRAFT_CONFLICT。提交后到达的旧保存请求必须拒绝，不能把 submitted 改回 inProgress。

草稿保存和已完成结果查询不因内容维护暂停；正式交卷冻结时返回可恢复错误并保留草稿。账号停用仍独立限制写操作。

## 3 类目结构变化

### 3.1 不变式

parentId=null 表示一级；depth 只能 1、2、3；ancestorIds 为从根到父的无重复路径。每个节点恰有一个父级，移动后子树中最深节点不得超过三级。规范名称去首尾空白并进行统一 Unicode 规范化，同级规范名称唯一。

每张卷只有一个当前 categoryId。父类目汇总其直接挂卷及全部后代挂卷，每个 paperId 只取一份 bestScore。题库分类不参与计分。

### 3.2 预览

后台请求 category.change.preview 提交 expectedTreeVersion 与操作列表。服务端生成只读计划：树差异、被迁题目、被迁试卷、受影响会员数量、分类重建范围和预计维护影响，返回 previewId 与 planHash。

确认接口必须绑定预览、树版本、目标 ID、操作者和原因。源版本变化则预览过期，不能使用旧人数和旧目标执行。预览不写正式分类，也不能凭前端提交的 planHash 信任不存在的服务端计划。

### 3.3 执行与失败恢复

1. 事务设置结构任务占用与 contentWrites、attemptStart、attemptSubmit 维护标记；支付和草稿保存不受影响。
2. 等待关闭前已经读取旧状态的事务排空。依据当前数据库事务最大 30 秒限制，工作器记录 notBefore=关闭成功时刻+35 秒后再推进，不在单个函数中阻塞等待；上线前须验证该上限与实际调用重试边界，若改变则同步调整。
3. 获得独占结构任务租约，所有内容写入口都校验该任务与维护标记。分批记录前值及后值，修改节点、名称占位和题卷分类；读页面在此阶段返回结构更新提示，不能读到一半旧树一半新树。
4. 按 paper_bests 和迁移后的树重新生成分类 score_metrics 的新 generation，保留旧投影；总榜、周月指标及总分不改。
5. 校验无循环、层级合法、当前引用有效、每个用户的分类分可追溯，同一根下的直接挂卷加子树分等于该根分。树版本与新分类 generation 一次性切换。
6. 清除维护标记，开放开始与交卷，触发分类排行榜新快照；旧快照失效显示更新中，不展示新树下的旧排名。

中断后按 job cursor 和每对象前后摘要接续，重复步骤不重复迁移。不能仅因租约过期就宣布成功或自动开放入口。回滚采用保存的前值和旧指针；若已切换且重新开放写入，必须新建反向维护任务，不能覆盖之后的新业务。

CloudBase 的上述事务限制来自[官方事务文档](https://docs.cloudbase.net/database/transaction)。排空等待是本项目设计，必须通过并发验收，不是平台自动提供的维护能力。

### 3.4 删除与停用

有子节点先迁移或逐层处理，有当前题目或试卷引用先指定目标迁移。只有历史快照引用时可逻辑删除，旧路径保留为文字快照。删除后不能复用 ID；同名重建是新节点。

停用节点使该节点及其后代不再供新卷发布和新答题选择，但不删除引用与历史成绩。已有答题仍按试卷快照和撤回状态判断；停用不是紧急撤回。分类排行隐藏被停用路径，累计总榜、周月榜仍保留合法分数；重新启用后恢复该分类的现有成绩。

## 4 大批导入的原子可见性

CSV 最多 1000 行，分为 uploaded、validated、staging、committed、failed。先完成全文件校验和重复检查，再接受确认。文件摘要、列规范、当前类目版本和预览摘要全部绑定。

分批写入 import_rows、题目草稿和 source_keys，占位使用事务保护。每条草稿携带 batchId；在 import_batches 为 committed 之前，任何列表、按 ID 读取、试卷引用和发布接口都不得把它当成有效内容。

全部行数量、摘要与引用核对后，用一个小事务将批次置 committed，整批在业务上同时可见。这不是宣称 1000 条文档在一个物理事务里完成。提交前再次检查类目版本；变更时阻止提交，重新校验。

同文件重传读取原批结果。失败批的占位只有在确认未 committed、无有效下游引用且持有本批租约后才能释放；不能清理其他批次。未知状态先查原批，不重新生成不同批号再次导入。

## 5 排行与公开隐私

score_metrics 是服务端即时维护的个人指标，公开榜为完整发布的一代 ranking_rows。四个 scope 统一包含免费与 VIP 卷，不保存 accessFilter。

工作器认领脏榜任务，按稳定会员 ID 分页采样，取得该榜正分指标和参与状态；完成采样后按 value 降序、reachedAt 升序、memberId 升序排序，计算并列 1、1、3。写入全体参与者的名次行以支持前百之外的本人名次，前台仅公开 rank<=100 的行并包含边界并列。

每代记录 sampleStartedAt、sampleEndedAt；这是该轮采样集合的内部一致排名，不声称是数据库跨集合某一毫秒的全局快照。新注册或采样期间变化进入下一轮，脏任务在采样中新增的标记不能被旧任务清除。页面显示更新时间，名次及前一名分差必须来自同一 generation，不能混用即时分值伪造排名。

写齐行数及摘要后才切换 ranking_heads，失败继续提供上一完整代并提示延迟。正常更新目标为 60 秒内，定时任务兜底、交卷事务持久刷新标记；正式容量和触发周期由压测确认。超过目标时显示榜单更新延迟并报警，不伪造刷新时间。

关闭公开排行立即拒绝该会员新的公开展示，旧快照返回前二次核对成员状态并过滤昵称与头像。过滤导致的名次仍属旧快照，界面标明等待刷新，不拿分页序号冒充新排名。新快照完成后所有名次重排；同样处理注销及禁榜。本人可以查私人总分，未参与时不返回公开名次。

## 6 成绩纠错

先撤回有问题的试卷，保留旧答案和旧结果。预览绑定受影响版本、修正答案摘要和有效尝试集合。确认后关闭交卷入口并排空，防止新旧评分混写；本轮首版选择全站短时交卷维护，不引入复杂分片锁。

按每会员每试卷的 scoreSeq 重放全部有效尝试。示例原序列 60、80、70，修正后为 90、80、70，则累计最高分从 80 调至 90，各次分差重算为 90、0、0，并归回各自原交卷周期。仅修改当前最高分而不改周月事件是错误实现。

原评分与事件不覆盖，生成 gradeRevision、新结果及补偿事件，重建该用户受影响的总分和各指标。保留注册及历史勋章，按新总分计算当前等级。每用户处理事务幂等，任务失败保持维护并显示真实状态；全量检查后切换视图和开放交卷。

## 7 任务租约与重放

jobs 状态为 queued、running、retryable、needsReview、succeeded、cancelled。获取租约时递增 fencingToken；每次写入检查当前令牌，旧工作器恢复后也不能继续覆盖新工作器结果。

定时触发允许重复，不能假定仅一实例。单轮限制时间和记录数，保存 cursor 后交回调度。对可以幂等确认的内部步骤有限重试；外部支付、退款结果未知先查同一业务号。超过次数或摘要冲突进入 needsReview，不自动新建第二笔业务。

只有成功持久化了任务才向上游返回已受理。原始调用失败和业务处理失败分别记录 requestId、jobId、错误码，不把重试次数当成完成进度。
